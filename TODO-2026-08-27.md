## P1 — correctness holes on the paths people actually use

### P1-1. Android camera backup will re-upload everything

`PhotoUploadWorker` treats `MediaStore.Images.Media.DATE_TAKEN` as
**seconds** (`since / 1000` in the selection query) but then passes
`item.dateTaken` to `Date(…)` as milliseconds. On Android, `DATE_TAKEN`
is milliseconds. The watermark `last_photo_ts` is also milliseconds.
Result: the inequality `DATE_TAKEN> now_ms/1000` is true for essentially
every photo, every 30-minute run. Combined with `conflict=rename`, that
is a conflict-copy storm under `/Camera Uploads/`, not a missed backup.

Fix: one clock, milliseconds, watermark = max successful `DATE_TAKEN`
(not `System.currentTimeMillis()` after a partial batch). Advance per
successful file, not “any success ⇒ now”. Test with a fixture cursor
if practical; otherwise document a manual proof.

**Evidence:** `android/app/src/main/java/com/xxdrive/app/PhotoUploadWorker.kt`
35–60, 72–76.

**Owner:** mill.

### P1-2. Android native login does not log the WebView in

`LoginActivity` POSTs `/api/auth/login` via OkHttp (no cookie jar),
stores the bearer in `SharedPreferences`, then `MainActivity` loads
`Session.baseUrl + "/"` in a WebView **without** injecting
`Authorization` or copying `Set-Cookie` into `CookieManager`. The PWA
`boot()` calls `/api/auth/me` with credentials-same-origin cookies
and falls back to `showLogin()`. Users sign in twice. Downloads use
the bearer; browsing does not.

Fix: on successful native login, set the session cookie on the
WebView’s `CookieManager` for `baseUrl` (HttpOnly is server-set —
use the login response `Set-Cookie`, or call `/api/auth/fabric` /
login from the WebView). Do not expect OkHttp and WebView to share
storage.

**Evidence:** `LoginActivity.kt` 69–78; `MainActivity.kt` 87;
`internal/webfs/static/app.js` 94–100.

**Owner:** mill.

### P1-5. SPA share URLs double-prefix when `-base-url` is set

Create-share uses `location.origin + "/s/" + r.token` (full capability
token — good). Existing-share list does `location.origin + s.url`,
and `handleShareList` sets `url` to `shareURLPrefix() + "/s/" + hash16`.
When `XXD_BASE_URL` is set, `s.url` is already absolute →
`https://hosthttps://drive…`. When unset, `s.url` is `/s/hash16` and
the concat works.

Fix: SPA should prefer `s.url` if it is absolute, else
`location.origin + s.url`. Server should return a single canonical
URL (full token or hash16 — pick one and freeze in API.md). Hash16
short URLs are a deliberate feature (`resolveShare`); do not silently
drop them.

**Evidence:** `internal/webfs/static/app.js` 808–836;
`internal/api/shares.go` 41–46, 118–123, 127–151.

**Owner:** mill.

### P1-8. Login timing oracle

`handleLogin` skips PBKDF2 when the username does not exist
(`err != nil || … !CheckPassword`). ~0 ms vs ~400 ms at 600k
iterations. Rate limit is 10 / 15 min / IP+user. Dummy-hash a
missing user with a constant unusable salt (same iterations) before
returning 401. Do not add usernames to the 401 body (already
generic).

**Evidence:** `internal/api/handlers.go` 61–65; `docs/MANUAL.md` §5
LOW list.

**Owner:** mill.

### P1-9. CSRF origin vs the TLS proxy `Host`

`sameOrigin` compares stripped `Origin`/`Referer` host to `r.Host`.
If the fabric/tailscale proxy rewrites `Host` to `127.0.0.1:8080`,
cookie mutations 403. Bearer clients are exempt. Fix is proxy
config (`Host` = public name) **or** comparing against configured
`-base-url` host. Do not trust a client-supplied Host override.
Document the required proxy snippet in MANUAL troubleshooting
(already hinted). Prove with a test that Origin
`https://drive.example.com` passes when `r.Host` is that name and
fails when `r.Host` is `127.0.0.1:8080`.

**Evidence:** `internal/api/server.go` 178–192;
`docs/MANUAL.md` §8 403 paragraph.

**Owner:** mill (test + optional `-base-url` compare) · operator
(proxy Host).
